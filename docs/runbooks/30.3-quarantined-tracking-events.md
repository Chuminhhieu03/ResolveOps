# Runbook 30.3: Quarantined Tracking Event Remediation

> **Severity:** Medium (Sev-3)  
> **Reference:** Master Specification §6, §11 (Scenario 4), §30.3, §24 Phase 6 & 16  
> **Target Entity:** `quarantined_events` / `inbound_event_receipts`

---

## 1. Overview & Triggers

When an inbound carrier tracking event cannot be matched to an active shipment leg or tracking alias, Master Spec §11 (Scenario 4) mandates that the event must NOT be discarded silently. It is stored in `quarantined_events` with `QuarantineStatus.Quarantined` and a descriptive `quarantine_reason` (e.g. `ERR_SHIPMENT_NOT_FOUND`, `ERR_CARRIER_MISMATCH`).

### Alert Triggers
- **Prometheus / Seq Alert:** `QuarantinedEventsCount > 50` in 1 hour.
- **Metric:** `resolveops.tracking.events.quarantined`.

---

## 2. Diagnostics & Inspection

Execute query to inspect recent quarantined receipts:

```sql
SELECT TOP 20
    q.id AS quarantine_id,
    q.tenant_id,
    q.carrier_id,
    q.tracking_number,
    q.quarantine_reason,
    q.created_at_utc,
    r.source_system,
    r.raw_payload
FROM quarantined_events q WITH (NOLOCK)
INNER JOIN inbound_event_receipts r WITH (NOLOCK) ON q.inbound_receipt_id = r.id
WHERE q.status = 'Quarantined'
ORDER BY q.created_at_utc DESC;
```

---

## 3. Remediation Workflow

### Case 1: Shipment Was Created Late (Timing Race Condition)
If the external shipper EDI arrived after the carrier tracking scan:
1. Search for newly created shipment matching the tracking number:
   ```sql
   SELECT s.id AS shipment_id, l.id AS leg_id, s.external_reference
   FROM shipments s
   LEFT JOIN shipment_tracking_aliases a ON a.shipment_id = s.id
   LEFT JOIN shipment_legs l ON l.shipment_id = s.id
   WHERE s.tenant_id = @TenantId
     AND (s.external_reference = @TrackingNumber OR a.tracking_number = @TrackingNumber);
   ```
2. If found, re-ingest the quarantined receipt using the Resolution API:
   ```http
   POST /api/integrations/quarantine/{quarantineId}/resolve
   Content-Type: application/json
   Authorization: Bearer <token>

   {
     "shipmentId": "<shipment_id>",
     "shipmentLegId": "<leg_id>",
     "notes": "Late shipment EDI ingested; linked manually."
   }
   ```
3. The API transitions the quarantined record to `Resolved` and enqueues a new `TrackingIngestionRequestedV1` event.

### Case 2: Tracking Alias Missing
If the carrier provided a secondary tracking barcode:
1. Add the alias to the existing shipment via `POST /api/shipments/{id}/aliases`.
2. Reprocess the quarantined event.

### Case 3: Legitimate Noise / Non-Tenant Shipment
If the carrier erroneously sent tracking data for another customer:
1. Mark the event as `Dismissed`:
   ```http
   POST /api/integrations/quarantine/{quarantineId}/dismiss
   Content-Type: application/json
   Authorization: Bearer <token>

   {
     "reason": "Tracking number belongs to third-party customer; carrier misrouted webhook."
   }
   ```

---

## 4. Verification

1. Verify the quarantined event status updated to `Resolved` or `Dismissed`.
2. Verify that `tracking_events` now contains the canonical normalized tracking event.
3. Check if any exception policy (e.g. Delayed Delivery) was evaluated and triggered.
