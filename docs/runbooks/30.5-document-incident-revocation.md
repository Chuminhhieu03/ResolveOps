# Runbook 30.5: Document Incident & Presigned URL Revocation

> **Severity:** High (Sev-2) / Critical (Sev-1 if sensitive data or malware involved)  
> **Reference:** Master Specification §19.6, §30.5, §24 Phase 9 & 16  
> **Target Subsystem:** `ResolveOps.Modules.Documents` / MinIO S3 Object Storage

---

## 1. Incident Scenarios & Objectives

This runbook applies to:
1. **Malicious / Compromised File:** An uploaded file is discovered to be malware, ransomware, or spoofed content after passing initial upload.
2. **Confidentiality Breach / Wrong Document Linked:** A sensitive commercial invoice or confidential contract was attached to the wrong tenant case or shared with an external carrier.
3. **Compromised Presigned URL:** An active download URL was intercepted or leaked.

### Primary Objectives:
- Instantly revoke access to the document.
- Isolate / quarantine the physical blob in MinIO S3.
- Invalidate all issued presigned URLs.
- Conduct audit log forensics.

---

## 2. Immediate Containment Procedure (Execute in < 10 Minutes)

### Step 2.1: Revoke Document Status in Database
Instantly revoke the document availability:
```sql
UPDATE evidence_documents
SET status = 'Quarantined',
    scan_status = 'Quarantined',
    concurrency_stamp = NEWID(),
    updated_at_utc = SYSUTCDATETIME(),
    updated_by = 'SECURITY_INCIDENT_RESPONDER'
WHERE id = '<compromised_document_id>'
  AND tenant_id = '<tenant_id>';
```
*Effect:* Any subsequent API request to download, preview, or bundle the document will return `404 Not Found` or `403 Forbidden` (`DocumentStatus.Quarantined` cannot be accessed).

### Step 2.2: Move / Quarantine Object in MinIO S3
Using MinIO Client (`mc`):
```bash
# 1. Inspect object path
# Path format: resolveops-documents/tenants/<tenantId>/<documentId>/<fileName>

# 2. Move object to isolated quarantine bucket (no presigned URLs allowed)
mc mv myminio/resolveops-documents/tenants/<tenantId>/<documentId>/<fileName> \
      myminio/resolveops-quarantine/tenants/<tenantId>/<documentId>/<fileName>

# 3. Verify object is no longer present in primary bucket
mc ls myminio/resolveops-documents/tenants/<tenantId>/<documentId>/
```

### Step 2.3: Invalidate Active Presigned URLs
MinIO presigned URLs are HMAC-signed with the S3 access credentials.
- By moving the underlying object (Step 2.2), any existing presigned URL pointing to the original key immediately returns `404 NoSuchKey`.
- In extreme multi-document compromise events, rotate the MinIO service credentials immediately in environment secrets and restart API instances.

---

## 3. Forensic Audit & Evidence Preservation

### Step 3.1: Query Document Access Logs
Search Seq / Audit logs for all downloads or presigned URL requests for this document:
```text
@Message like "%GenerateDownloadUrl%" and DocumentId = "<compromised_document_id>"
```
Extract:
- Requesting IP addresses
- User IDs / Actor IDs
- Timestamps (UTC)
- HTTP User-Agent headers

### Step 3.2: Check if Document Was Shared with External Carriers
```sql
SELECT c.claim_number, cr.carrier_id, c.status
FROM claims c
INNER JOIN carrier_claim_responses cr ON cr.claim_id = c.id
WHERE c.case_id = (SELECT case_id FROM evidence_documents WHERE id = '<compromised_document_id>');
```
If the claim was already submitted with this document attached, contact the carrier claims representative immediately to request redaction.

---

## 4. Resolution & Post-Mortem

1. If a valid, clean document exists, upload replacement with `VersionNumber = VersionNumber + 1` and mark `SupersedesDocumentId`.
2. File incident report under `docs/security/incidents/INC-<YYYYMMDD>-DOC.md`.
3. Retain the quarantined binary in the isolated bucket under legal hold if required for forensic investigations.
