# Runbook 30.7: Database Point-In-Time Restore & RPO / RTO Verification

> **Severity:** Critical (Sev-1) / Disaster Recovery Drill  
> **Reference:** Master Specification §20.6, §30.7, §24 Phase 16  
> **Target System:** Microsoft SQL Server 2022 (`ResolveOps` Database)

---

## 1. Objectives, RPO & RTO Targets

| Metric | Target (Spec §20.6 & §30.7) | Tested Capability |
|---|---|---|
| **Recovery Point Objective (RPO)** | **&lt; 5 minutes** (Maximum data loss window) | Achieved via Full nightly backup + Hourly Differential + 5-minute Transaction Log backups. |
| **Recovery Time Objective (RTO)** | **&lt; 30 minutes** (Service restoration duration) | Automated restore script to standby container completes in < 12 minutes. |

---

## 2. Backup Architecture & Locations

- **Full Backups:** Daily at 01:00 UTC (`s3://resolveops-backups/mssql/full/`)
- **Differential Backups:** Every 4 hours (`s3://resolveops-backups/mssql/diff/`)
- **Transaction Log Backups:** Every 5 minutes (`s3://resolveops-backups/mssql/tlog/`)

---

## 3. Step-by-Step Point-in-Time Restore Procedure

### Step 3.1: Choose Target Point-In-Time Timestamp
Identify the exact recovery point in UTC (e.g., `2026-09-25 04:30:00 UTC`) right before data corruption or disaster occurred.

### Step 3.2: Restore to an Isolated Standby Environment
**DO NOT restore over production directly without verification.**

In an isolated staging / verification SQL Server instance:

```sql
-- 1. Restore Full Backup with NORECOVERY
RESTORE DATABASE [ResolveOps_Restored]
FROM DISK = '/var/opt/mssql/backups/ResolveOps_FULL_20260925_010000.bak'
WITH NORECOVERY,
     MOVE 'ResolveOps' TO '/var/opt/mssql/data/ResolveOps_Restored.mdf',
     MOVE 'ResolveOps_log' TO '/var/opt/mssql/data/ResolveOps_Restored_log.ldf',
     REPLACE;

-- 2. Restore Latest Differential Backup with NORECOVERY
RESTORE DATABASE [ResolveOps_Restored]
FROM DISK = '/var/opt/mssql/backups/ResolveOps_DIFF_20260925_040000.bak'
WITH NORECOVERY;

-- 3. Restore Transaction Log Backups up to Point-In-Time with RECOVERY
RESTORE LOG [ResolveOps_Restored]
FROM DISK = '/var/opt/mssql/backups/ResolveOps_TLOG_20260925_043500.trn'
WITH RECOVERY,
     STOPAT = '2026-09-25 04:30:00';
```

## 4. Integrity Verification & Validation Checklist

Before switching traffic to the restored database, the operator must execute the following 5 verification queries:

### Check 4.1: Database Schema & Migrations Check
```sql
SELECT TOP 1 MigrationId, ProductVersion
FROM [ResolveOps_Restored].[dbo].[__EFMigrationsHistory]
ORDER BY MigrationId DESC;
```
*Expected Result:* Matches latest migration (e.g. `20260923151333_AddReportingAndCarrierScorecards`).

### Check 4.2: Tenant Record Counts
```sql
SELECT COUNT(*) AS total_tenants FROM [ResolveOps_Restored].[dbo].[tenants];
```
*Expected Result:* Matches production tenant count prior to incident.

### Check 4.3: Financial Integrity & Claim Balances
Verify that all claim amounts, approved balances, and recovery transactions reconcile:
```sql
SELECT
    COUNT(*) AS inconsistent_claims
FROM [ResolveOps_Restored].[dbo].[claims] c
WHERE c.recovered_amount > c.approved_amount
   OR c.approved_amount > c.claimed_amount;
```
*Expected Result:* 0 inconsistent records.

### Check 4.4: Outbox / Inbox Status
```sql
SELECT processing_status, COUNT(*)
FROM [ResolveOps_Restored].[dbo].[outbox_messages]
GROUP BY processing_status;
```

---

## 5. Traffic Cutover Procedure

1. Place API instances in maintenance mode (read-only / 503).
2. Take a tail-of-log backup of the failing database if accessible:
   ```sql
   BACKUP LOG [ResolveOps] TO DISK = '/var/opt/mssql/backups/ResolveOps_TAIL.trn' WITH NORECOVERY;
   ```
3. Rename the verified restored database to active:
   ```sql
   ALTER DATABASE [ResolveOps] SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
   ALTER DATABASE [ResolveOps] MODIFY NAME = [ResolveOps_PreDisaster];
   ALTER DATABASE [ResolveOps_Restored] MODIFY NAME = [ResolveOps];
   ALTER DATABASE [ResolveOps] SET MULTI_USER;
   ```
4. Restart API and Worker services; verify `/health/ready` returns `Healthy`.
5. Document actual measured RPO and RTO in the post-mortem report.
